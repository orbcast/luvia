# 应用目录

Luvia 是一个视频播放器。`apps/` 主要按可独立运行、构建与发布的应用组织，也暂时容纳未来可能拆仓的源规则目录。各应用可采用不同语言和框架，技术栈与平台支持范围由应用自身维护，不要求共享 Go/MyGo 工具链。

## 当前目录

| 目录 | 技术栈 | 当前功能与入口 |
| --- | --- | --- |
| [desktop/](desktop/README.md) | Go + MyGo 原生 UI | 当前仍为待办清单示例，尚未实现视频播放；开发与验证见应用 README，编码约束见 [AGENTS.md](desktop/AGENTS.md) |
| [luvia-rules/](luvia-rules/README.md) | 源规则与资源源 | 维护播放器所用的源规则与资源源；目前仅有说明，未来随时可能迁移到独立仓库，不是可运行应用 |

Swift / SwiftUI 等是未来可选技术栈，目前没有对应工程。只有明确需求后才新建应用，不预建空项目。

## 新增应用

- 建立 `apps/<name>/`，以清晰的应用身份或用途命名，不以某种框架约束整个目录。
- 使用适合自身技术栈的工程结构、依赖清单和锁文件，例如 Go module、Swift Package 或 Xcode 工程；这是形式示例，不要求每端具备全部配置。
- 添加应用 README：说明用途、技术栈与版本、源码布局、环境依赖、开发/测试/构建命令、产物、平台范围与已知限制。
- 添加应用 `AGENTS.md`：继承根规范，细化本端的代码位置、UI/状态生命周期、并发、测试、资源和发布约束。技术规则只在所属应用范围生效。
- 明确应用标识、数据目录与资源来源；只在需要公共入口时扩展根目录工具，并在命令说明中写明覆盖对象。

## 依赖与复用

应用可以依赖 [packages/](../packages/README.md) 的适用模块，不导入其他应用的入口或内部实现。共享模块需声明语言和平台兼容性，不假定 Swift 能直接导入 Go 包；跨语言优先评估数据格式与协议，实际需要桥接时再记录其边界和构建成本。

共享品牌母版从 [assets/](../assets/README.md) 获取，本端资源配置和平台生成格式留在应用内。当前根目录 `make dev`、`make test`、`make check`、`make build` 默认服务 `apps/desktop`，不代表未来应用或全部共享模块已验证；其他应用按本地说明执行对应工具。

共同治理规则见根目录 [AGENTS.md](../AGENTS.md)。
