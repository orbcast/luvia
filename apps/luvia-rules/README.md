# Luvia Rules

Luvia 是一个视频播放器。`luvia-rules` 维护播放器使用的源规则和资源源，描述资源从哪里来、如何发现与解析。这里的“源”指内容或资源的来源，不是播放器应用的源代码。

规则是纯数据 JSON，由 desktop 的解释引擎执行；格式、字段、步骤词表与错误分类以 [源规则格式（Rule DSL）](../../docs/rule-dsl.md) 为准，本文件只说明本目录的组织与维护方式。

## 目录结构

```
apps/luvia-rules/
  <source-id>/          # 一个上游一个目录，目录名即规则的 id
    rule.json           # 规则本体，id 必须等于目录名
    fixtures/           # 各操作的响应样例，供离线验证
    README.md           # 来源、覆盖范围、授权与已知限制
```

当前包含：

| 目录 | 来源 | 覆盖 | 说明 |
| --- | --- | --- | --- |
| `kanju/` | `https://kanju1.com/` 的公开接口 | 首页、列表与搜索、当日更新、详情、选集、线路解析 | 带 HMAC 签名的 JSON 接口；搜索靠 `intent=search` 才按关键词匹配；当日更新取 `/v1/watch-calendar` 的周表，每天每类上游只给 6 条预览 |

同一上游的多条播放源与线路是运行时数据（响应中的线路数组），不拆成多个目录；分类差异用规则里的 `kindValues` 处理。

## 维护边界

本目录承载源规则、响应样例与必要说明，不承载播放器 UI、播放引擎或其他应用内部业务。规则按实际来源组织，不为未知需求预建目录或抽象层。

新增规则时同时说明来源站点、覆盖范围、授权或使用条件、已知限制与验证方式；`fixtures/` 要覆盖正常、空结果与缺字段等边界，不以真实网络是否在线作为唯一证据。规则不引用 `apps/desktop` 的 Go 类型、构建产物或其他内部实现，只通过规则文件与播放器连接。工具依赖与命令写在本目录，不使用本机绝对路径。

## 验证

在仓库根目录执行：

```sh
make rules-verify
```

它用规则自带的 `fixtures/` 与本地替身跑通五个操作，不访问真实上游；`make check` 也会覆盖这些用例。规则加载失败时不会拖垮整个播放器：目录会被跳过，并在诊断中给出文件、步骤位置与原因。

`fixtures/` 与实际响应结构漂移时需要更新样例与规则；只改样例不改规则、或反过来，都会让验证失去意义。真实网络冒烟属于手动检查，不作为提交证据。

## 随时可能迁移到独立仓库

`luvia-rules` 暂放在当前仓库的 `apps/` 下，**未来随时可能迁移到一个独立仓库维护与发布**。当前位置不代表它是可运行的应用，也不意味着它必须长期随播放器主仓库维护。

新增内容时保持目录自包含：使用目录内的相对引用，记录规则与资源的来源、必要的授权信息、格式和使用说明；不要依赖仓库根目录的隐式行为。播放器通过规则目录加载，因此拆仓后调整加载来源即可，无需复制播放器内部实现。实际拆仓时需同步消费者引用与获取方式，并维护格式兼容性；当前不创建独立仓库、不配置远程地址，也不提前设计发布系统。
