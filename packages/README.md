# 可复用模块

`packages/` 存放多个实际消费者共用的模块，例如数据格式解析、校验规则或存储协议能力。模块可以使用 Go、Swift 等适合其消费者的语言与工具链。目前仅建立目录与说明，尚无共享代码模块；本目录本身不是 Go module 或 Swift Package。

## 放什么

- 已确认至少有两个实际消费者的能力，按清晰职责放入 `packages/<name>/`，避免含糊的 `utils`、`common` 大包。
- 按实际语言组织工程，例如 Go module 的 `go.mod` 与 `*_test.go`，或 Swift Package 的 `Package.swift`、`Sources/` 与 `Tests/`；只创建所选技术需要的结构。
- 每个模块维护 README，说明用途、公开 API、示例、消费者、语言/平台兼容性、依赖、测试命令与限制；按需添加局部 `AGENTS.md`。

## 不放什么

仅供一个应用使用的实现、页面、窗口状态与控件绑定留在对应 `apps/<name>/`。共享品牌母版放入 [assets/](../assets/README.md)，开发脚本放入 `scripts/` 或根目录工具入口。不为未来需求预建空模块或框架。

## 依赖与跨语言边界

共享模块不能依赖应用内部实现，不持有应用窗口或共享可变全局。通过明确的数据类型、参数与必要的最小接口/协议协作；业务核心独立于具体 UI，不把某个应用的生命周期强加给其他消费者。

共享目录不代表语言之间可以直接互相导入。先确认消费者的语言和平台，优先评估共享数据格式、协议与契约；只有确有需求时才引入 FFI、桥接或代码生成，并记录构建、内存所有权、线程和错误边界。

## 接入与验证

按实际工程的发布路径、依赖管理和本地联调方式接入，不假定根目录已经有 `go.mod`、`go.work`、`Package.swift` 或 Xcode workspace。依赖清单与本地配置的影响范围必须明确。

在受影响模块中执行其 README 规定的单元测试、静态检查和必要构建，再验证受影响消费者。现有根目录 `make test` / `make check` 默认只检查 `apps/desktop`，不自动遍历共享模块。验证遵循根目录 [AGENTS.md](../AGENTS.md)，不让 Swift 模块运行 MyGo 检查，纯业务模块不默认启动 GUI。
