# 项目文档

`docs/` 存放项目正式维护的文档型内容，是人类与 Agent 共同查阅、理解和实施项目的资料目录。这里记录需要长期保留的事实、设计、约定和使用方式，不作为 Agent 的临时工作目录。

## 内容归属

适合放在这里的内容包括架构与模块边界、功能设计、数据格式与接口契约、长期有效的工程决策、开发与使用指南，以及需要持续维护的发布、运维或故障排查说明。只在有实际内容时新增文件或按主题分目录，不预建空目录和空模板。

根目录 [README.md](../README.md) 保持项目入口与导航，[AGENTS.md](../AGENTS.md) 维护 Agent 的项目级规则，[DESIGN.md](../DESIGN.md) 维护跨应用设计与深浅主题 Token，[CONTEXT.md](../CONTEXT.md) 记录背景及既有决策。应用/模块独有的构建、测试、技术栈与使用方式优先留在所属目录的 README / `AGENTS.md`。`docs/` 可链接这些权威来源，不复制一套相互漂移的规则。

当前尚未增加独立的架构或功能专题文档。新增正式文档时，在本 README 增补带用途说明的相对链接；文件名表达主题，避免 `temp`、`final-v2` 等临时命名。

## 查阅与维护

Agent 和人类在理解、实现或评审某个功能前，应查阅本目录与该任务有关的文档，并结合实际源码、测试与配置核实。文档应明确描述适用应用/平台、当前行为、约束和必要的验证方式；提案、规划、已实现能力及历史验证结果要区分，不将旧报告当作当前通过证据。

功能行为、接口、架构或开发流程变化时，在同一次变更中同步相关文档和本目录索引。发现文档与代码冲突，先核实事实并修正，不能按过期资料盲目实现，也不能擅自以代码现状否定已确认的需求。约束的适用范围仍遵循根目录与沿途 `AGENTS.md` 以及用户明确指令，不能借普通文档绕过这些规则。

## 临时内容边界

禁止放入 Agent 任务服务文件、任务计划、进度/状态文件、交接便笺、一次性脚手架、临时探测脚本、下载样本、截图、调试日志、测试输出和覆盖率报告。它们使用操作系统临时文件区域，执行完清理自己创建的内容；不能因为“是 Markdown”或“以后可能有用”就存入 `docs/`。

真正需要长期维护的测试策略、排障指南和工程决策可以放在这里，前提是整理为正式文档，去除运行垃圾、敏感信息和不可复用的本机路径，并说明适用范围。
