# 搜索页

搜索页（desktop）是一个关键词、本次会话的历史，以及数据源回答的片单。页面只持有视图状态：每个片单都来自数据源，追剧状态来自本地库。实现在 `apps/desktop/internal/search/`，配色与尺寸取自 [DESIGN.md](../DESIGN.md)，Token 集中在 `internal/design/design.go`。

## 一个关键词，一条轴

关键词是页面唯一的大号文字：`ui.SearchField` 保持输入、光标、清空与提交的全部原生行为，但把自身的表面、描边和圆角都设成页面底色，所以页面上只看得见放大镜、键入的字与占位提示。字号宽体 26、窄体 19，高度固定为 42（窄体 34）而不是随字号倍增——控件自己的行高会把高度推得更大。搜索框读一眼、打几个字，不是标题：词再大就会把排头挤下去，一屏能看的结果变少。

关键词下方是一条贯穿页面的横线，末端收一段 `accentRun`（28 个逻辑单位）的强调色短线。同一个横线又是每个结果分组的排头，所以关键词与它下面所有分组读起来是一列文字，而不是若干块卡片。

会话历史（本次会话最多 8 个关键词）作为小号文字排在关键词同一行的右侧，最新的一个用正文色，其余用弱化色，悬停提亮，点击即重新搜索。历史只活在本次会话内，不进 `library.json`。

## 结果分组

结果按内容类型分成有序的条带（术语见 [UI 术语表](terminology.md) 的 Search Shelf / 结果分组），顺序固定为剧集、电影、动漫、综艺，数据源给出顺序之外的类型排在最后。**只出现有结果的类型**，一部电影的一次搜索只有一个分组。

每个分组由三部分组成：一条 1px 横线、线下的一行（类型名 15 / 600 + 该类型的数量 12 / 弱化色）、两行海报。数量是本次回答里该类型的条数（`{count} 部` / `N titles`），不复用资源库的“部资源”文案。

海报是"被拿在手上的图"：图片本身就是卡片，圆角 12，6% 描边，没有底板和外框；图上叠画质徽章、追剧按钮、地区与年份，底部有一层 75% 黑到透明的遮罩保证文字可读。图下方没有横线，直接是标题（15 / 600，单行截断，命中的关键词用强调色）和第二行：剧集与动漫显示"更新中 / 已完结 · 集数"（强调色，带火苗图标），其余显示"年份 · 地区"（弱化色）。

宽体布局的海报列**铺满内容宽度**：列数由宽度推出（每列不低于 128、最多 8 列），间距固定 20，海报吃掉剩下的宽度，所以一排的右端与排头横线、关键词下的强调短线对齐，不再在右边留一条空带。窄窗口（`design.Docked`）只是宽度变小，规则相同，仍保证至少两列。每个分组最多显示两行，扫描结果时不必滚动到底。

## 四种状态

- **输入中 / 搜索中**：上一批结果留在屏幕上，关键词下方多一行 spinner 与说明，页面不会在两次关键词之间变空。只有第一次搜索且还没有任何回答时才不画结果区。
- **上次搜索**：输入框被清空但屏幕上仍有上一批结果时，这些结果留在一个排头为"上次搜索 · 关键词"的分组里，右侧提供"重新搜索"。这个状态优先于"起始"，所以清空输入框后页面只说一件事，不会同时出现"搜索资源库"和一堆旧结果两套互相矛盾的说法。
- **起始**：没有任何结果也没有关键词时，给一句说明加一个示例提示；若本次会话已有历史，则改为列出可点击的历史关键词（标题"最近 · 本次会话"）。不预置只出过一两次的真实数据，也不假装数据源里有内容。
- **无结果**：标题"「关键词」没有结果"，一句说明点出是哪个源没有匹配，一句不点名的重试提示，一个"重试"入口，最后一条细线上方指向资源库的分类浏览。**不列出任何未经验证的关键词**——会话历史里的词只是用户搜过的，不代表有结果。
- **失败**：错误说明加一个反差底的重试按钮，已拿到的结果仍显示在下方，重试不会让页面从空白开始。

## 文案与验证

界面文案走 `locales/en.json`（源语言）与 `locales/zh-Hans.json`，`go tool mygo generate` 生成 `catalog_gen.go`，视图只调用生成函数；新增键必须成对出现。图标只用 `assets/ui-icons/solar/` 的 Solar 资源，经 `internal/icons` 的 `Parse` 取用，不手写 SVG。

行为由 `apps/desktop/internal/search/page_test.go` 的无窗口用例覆盖：关键词提交、历史保留、命中高亮、分组顺序、无结果重试、清空后标注上次搜索、空态不点名未验证的词、窄布局列数。整体闸门为仓库根的 `make check`。
