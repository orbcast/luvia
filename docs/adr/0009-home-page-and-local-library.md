# 0009 发现页由源规则首页与本地观看库组合

- 状态：已采纳
- 日期：2026-11-16

## 背景

用户要求按设计稿实现发现页：Hero 区域轮播、沉浸式 Banner、继续观看、本周追剧，且只用 MyGo 原生 UI。片单可以由源规则的首页操作提供，但观看进度与追剧是用户自己的数据，任何上游都不知道，也不应该交给规则表达。设计稿里的 Hero 是艺术化的大图，规则没有“Hero”概念，上游首页只给分区与卡片。

同时，旧的解析层没有任何本地数据或图片通路：`source.Card` 只有海报与横幅 URL，图片是远程资源；发现页需要把远程图片解码成 `ui.Bitmap`，而解码必须在 UI 线程。

## 决定

发现页由 `internal/home` 组合三类依赖：`source.Source`（片单）、`library.Store`（本地进度与追剧）、`media.Loader`（图片）。页面不感知具体上游，换源只换 `Source` 实现。

Hero 取首页分区中横幅最多的一个分区，最多四项；没有横幅时回退到首个非空分区。6 秒自动切换、悬停暂停、右侧缩略图手动切换。这是布局启发式，不往规则里加 Hero 概念，避免每条规则都要描述运营位。

继续观看与本周追剧只读本地库：没有记录就显示空态，不填演示数据。周历以追剧记录的 `UpdatedAt` 按本地日期聚合，今天高亮。观看进度与追剧都以 `source.Ref` 为键，Payload 原样保存，格式为 version 1 的 JSON 并原子替换写入。

图片由 `media.Loader` 在后台下载、经 `mygo.RunOnMain` 解码，缓存键为 `sha256(url)`，内存加磁盘两级，单张上限 12 MB、并发 4。命中缓存不再发请求。

播放器与详情页尚未实现：主播放与影片详情按钮只触发回调，未接回调时给短暂提示，不跳转到假页面。视觉上把图像叠加 Token（压暗、侧向与底部遮罩、文字投影、图像上的进度条底色）收进 `internal/design`，AppShell 与页面共用一处定义。

## 后果

本地库与规则的边界清楚了：规则只管上游片单与线路，用户数据在本地，缓存属于上层，引擎仍不缓存。代价是发现页只能显示一个有进度的条目且需要真实观看行为才能看到内容，空态会长期出现在开发环境。

Hero 的启发式依赖上游首页给横幅；只给海报的源会落到回退分支，视觉效果更朴素，但不影响可用性。图片缓存按 URL 哈希累积，目前没有容量上限与淘汰策略；本地库格式变化时需要迁移代码。接入播放器后，提示文案与进度写入点会被替换，`source.Card.overview` 之后若出现更多界面字段，仍按“规则产出数据、界面决定排版”的方式扩展。
